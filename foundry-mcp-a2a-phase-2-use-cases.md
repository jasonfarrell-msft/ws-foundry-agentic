# Microsoft Foundry + MCP + A2A Workshop — Phase 2 Use Cases

For this workshop, treat **OGE** as **Oversight, Governance, and Efficiency** and use **zero-input scenarios** where attendees do not need to bring or upload any data.

## Selection criteria

- **Not simple, not complicated:** 2–3 specialist behaviors, 1 orchestrator, 1 critic, 1–2 MCP tools.
- **Microsoft Foundry + MCP + A2A visible:** each use case shows deployment, invocation, tool contracts, and agent handoff logic.
- **OGE aligned:** auditable decisions, explainability, human-in-the-loop checkpoints, and measurable workflow efficiency.
- **Zero-input:** all artifacts are pre-bundled or auto-seeded by setup scripts.

## Recommended core use cases (pick 2)

## 1) Policy Navigator & Control Mapper (**Recommended Core #1**)
- **Problem:** answer policy questions, map cited clauses to controls, and generate governance actions.
- **Microsoft Foundry:** hosted orchestrator + specialists with versioned prompts/instructions.
- **MCP tools:** policy search/read tool + task creation/notification action tool.
- **A2A pattern:** router -> policy clause specialist -> control mapping specialist -> action drafting specialist -> critic.
- **OGE fit:** strong governance traceability (clause -> control -> action) and clear oversight artifacts.

## 2) Access Anomaly Triage Simulator (**Recommended Core #2**)
- **Problem:** triage synthetic access anomalies against role policy and SoD rules, then recommend approve/remediate/escalate.
- **Microsoft Foundry:** prompt/hosted specialists with evals for consistency and risk rationale.
- **MCP tools:** access lookup/read tool + remediation ticket or attestation action tool.
- **A2A pattern:** router -> policy conformance specialist -> SoD specialist -> remediation specialist -> critic.
- **OGE fit:** governance control enforcement with auditable decisions and escalation gates.

## Optional stretch use case

## 3) Audit Readiness Scorecard Generator
- **Problem:** score readiness for selected controls, identify evidence gaps, and generate follow-up requests.
- **Why stretch:** high OGE relevance with moderate orchestration complexity and minimal data prep.
- **Use when:** the audience is advanced or core labs finish early.

## Zero-input workshop bootstrap (ready for attendees)

Distribute a single file: **`workshop-datapack-v3.zip`**
with two setup scripts:
- `setup/seed-workshop-data.sh`
- `setup/seed-workshop-data.ps1`

Attendee flow:
1. Clone repo
2. Run one seed script
3. Start labs

No attendee-provided files are required.

### Use case 1 data
- `uc1/policies/*.md` (10 files with stable clause IDs)
- `uc1/control_matrix.csv` (80 rows)
- `uc1/task_templates.json` (1 file)

### Use case 2 data
- `uc2/role_policy.csv` (120 rows)
- `uc2/sod_rules.csv` (40 rows)
- `uc2/access_records.csv` (100 rows; generated by seed script if missing)
- `uc2/justification_templates.md` (1 file)

### Stretch use case data
- `uc3/audit_checklist.md` (1 file)
- `uc3/evidence_index.csv` (150 rows; generated by seed script if missing)
- `uc3/audit_scope.csv` (8 rows)

### Shared assets
- `shared/schema/*.json` (A2A and MCP I/O contracts)
- `shared/scoring/*` (rubric + lightweight evaluator script)
- `shared/readme.md` (load order, run steps, expected outputs)

## Data guardrails

- No production data, no PII, no external API dependency for baseline labs.
- Markdown + CSV only in core path (no PDF parsing required).
- Include deterministic expected-output files for facilitator checks.
- Seed scripts must be deterministic (fixed random seed) so all attendees see the same results.
